## 2. UI 応答性（2 秒以内・ボタンが固まらない）

### 問題

管理画面・受講者画面でボタン操作後の応答が遅い（再読込・保存後に全画面ブロックなど）。

### 方針

- 初回読込のみ **ブロッキング loader**（`loading`）
- 2 回目以降は **`refreshing` + スピナー**（画面全体はブロックしない）
- 設定と回答は **並列取得**（`UI_RESPONSE_BUDGET_MS = 2000` を `appDataLoad.test.ts` で検証）
- 回答送信後は **全件再取得せず** `prependResponse` で先頭に 1 件追加
- storage イベントは **150ms debounce**

### 実装

- `shared/src/appDataLoad.ts`（新規）— `resolveRefreshMode` / `shouldShowBlockingLoader` / `resolveResponsesRoomId` / `loadAppDataBundle` / `prependResponse` / `createDebounced`
- `shared/src/useAppData.ts`（新規）— 上記ロジックを React フックに統合
- `admin-web/src/hooks/useAppData.ts` / `participant-web/src/hooks/useAppData.ts` — `@shared/useAppData` を re-export
- `shared/src/appDataLoad.test.ts`（新規）

## 3. 管理画面 403（Sheet API request failed: 403）

### 原因

- `AdminPage` が `loadSettings()` 由来の **local seed** の `roomId`（例: `room-demo-1`）を `useAppData` に渡していた。
- GAS 側は **`demo-room-001` のみ有効** → Invalid room で 403。

### 修正

- 管理画面から **固定 `roomId` オプションを削除**。
- 回答取得は **Sheet 読込後の `settings.rooms`** から `resolveResponsesRoomId()` で決定（localStorage の room と混同しない）。

## 6. GitHub Actions（最小 CI）

### ワークフロー

- `.github/workflows/ci.yml`
- トリガー: `main` への push / `main` 向け PR
- 手順: `install:all` → `npm test` → `typecheck`（両 Web）→ `build:all`
- 秘密情報不要（`.env.development` はコミットしない）

### README 更新

- セクション **「自動テストと CI」** を追加（108 tests、CI の説明、失敗しやすいポイント）
- CI バッジ: `![CI](https://github.com/shintaro0403/experteye360/actions/workflows/ci.yml/badge.svg)`

### CI 初回失敗と修正

- **現象**: GitHub Actions で typecheck が赤（exit code 2）、6 件の型エラー。
- **原因**: `pdfExport.ts` の `textAt` / `textLinesAt` の `color` デフォルト引数が `ink` の **リテラル型** に推論され、`ink2` を渡せなかった。ローカルでは `npm test` のみで typecheck していなかった。
- **修正**: `color: string` を明示。
- **教訓**: ローカルでも CI と同じく `typecheck` + `build:all` を回す。

### CI の今後（本セッションでは未実装）

- ブランチ保護（`main` で CI 必須）— リポジトリ設定
- `e2e.yml`（Playwright + Sheet モック）— 第 2 段階
- 実 Sheet E2E — Secrets + 手動/週次
