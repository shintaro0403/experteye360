### 3.4 人間が見るテスト範囲

**基本方針**

- 人間は A ランクだけ責任を持つ
- B は代表ケースだけ確認
- C は Vitest / CI / AI に寄せる

**主な A ランク**

- 5 問フローを最後まで通す
- iframe レイアウトを目視する
- 研修コード NG で名前・所属に進めない
- 管理者コードなしで管理 UI に入れない
- 受講者送信 → 管理者で回答が見える
- 別 `client` / 別 `room` に漏れない
- PDF 代表 1 件を目視する

### 3.5 マルチクライアント・テナント分離

**仕様上の設計**

- `clientId` で契約組織を分離
- `roomId` で同一クライアント内の研修回を分離
- 本番は Sheet API + Google スプレッドシート
- マスターブック `clients` で `clientId` → `spreadsheetId` を解決
- クライアントごとに `settings` / `rooms` / `responses` / `audit_logs` の 4 シート
- 研修コードは `rooms.accessCodeHash`
- 管理者コードは `clients.adminTokenHash`

**現実装**

- 保存先は `localStorage`
- キーは `expertEye360:settings` / `expertEye360:responses`
- `clientId` は実装で未使用
- `storage/sheet.ts`、GAS、`VITE_STORAGE_BACKEND` は未実装
- 受講者側は local の平文 `accessCode` で照合し、成功時に `roomId` を `sessionStorage` に保持
- 管理者側は local の平文 `adminAccessCode` で照合

**結論**

- 商材として複数クライアントに出す前提の設計はある
- ただし現在の実装はローカル開発版で、本番テナント分離は Phase 2.5 の実装が必須
- 画面や基本フローは活かし、保存・照合・分離境界を本番用に差し替える想定
