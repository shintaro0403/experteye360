## 8. TDD 呼称の整理

ユーザー指摘:

> TDD といいつつ先に実装があるから、厳密には TDD ではない

整理:

- Phase 0〜1 は、既存実装を正としてテストで固定する作業
- 厳密な意味の「新規機能を Red から設計する TDD」ではない
- 正確には以下の呼び方が近い
  - characterization test
  - regression test 追加
  - テスト付きリファクタ
  - TDD 風の Red → Green → Refactor

ただし今回の進め方としては、テストを先に書いて Red を確認し、最小実装・抽出で Green にしてから Refactor した。

未実装の Sheet API / PDF / OJT に入る Phase 2.5 / Phase 3 以降は、より本来の TDD に近い進め方が可能。
