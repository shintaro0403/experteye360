## 4. Phase 2 のテスト追加

Phase 2 は既存実装を正として固定する **characterization test / regression test** として進めた。

### 追加したテスト

- [shared/src/storage.test.ts](../shared/src/storage.test.ts)
- [shared/src/seed.test.ts](../shared/src/seed.test.ts)

### `storage.test.ts` の主な確認

- 初回 `loadSettings()` はデモ設定を返し、localStorage に保存する
- `saveSettings()` 後に `loadSettings()` で同じ設定を読める
- `saveSettings()` 時に settings が正規化される
- settings JSON 破損時はデモ設定に戻る
- `scenes` 空の settings はデモ設定に戻る
- `loadResponses()` 初回は `[]`
- responses JSON 破損時は `[]`
- `appendResponse()` 後、最新回答が先頭になる
- `saveSettings()` / `saveResponses()` は `expertEye360-storage` を発火する
- `resetDemoData()` は settings を初期化し responses を空にする

### `seed.test.ts` の主な確認

- `DEFAULT_SETTINGS` がデモシーンを 1 件以上持つ
- 各シーンが 5 問分の `questionCards` を持つ
- 各設問のカード配列が最大 5 件
- `tourUrl` / `rooms` / `adminAccessCode` を持つ

ユーザー指示:

先に [shared/src/sheetApi.test.ts](../shared/src/sheetApi.test.ts) を追加した。

### 固定した API 契約

- `GET settings` は `client` クエリを付け、`AppSettings` として読める
- `POST settings` は `client` + `token` クエリを付け、`AppSettings` を送る
- `GET responses` は `client` + `room` + `token` クエリを付け、回答配列として読める
- `POST responses` は `client` + `room` クエリと `ParticipantSubmission` ボディを送る
- `POST rooms/verify` は `accessCode` を送り、成功時に `roomId` を返す
