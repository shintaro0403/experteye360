## 3. 永続化 — 議論の結論（要約）

### 3.1 現状の問題（コード・`localStorage` のみ）

#### P-01

**問題** — 受講者の回答が講師の別端末に届かない（5173/5174 は別オリジン）

#### P-02

**問題** — クライアント・研修回のデータ混線

#### P-03

**問題** — 入室制限・URL 直アクセス

### 3.2 解決策（優先順・ドキュメント上の S-01〜04）

#### 1

**解決策** — **Sheet API + スプレッドシート**
**備考** — 必須。パスワードだけでは P-01 は直らない

#### 2

**解決策** — **`clientId`**（`?client=`）
**備考** — 複数クライアント時必須

#### 3

**解決策** — **`roomId` / 研修コード**
**備考** — 同一クライアントで複数研修がある場合推奨。正本は `rooms` シート

#### 4

**解決策** — **storage 抽象化**
**備考** — 将来 PostgreSQL 等へ API 差し替え可

### 3.3 DB・メモリ・FileZilla についての整理

#### Postgres 等は要る？

**結論** — 本番の共有ストアには **API 背後の永続化が必要**。MVP コードだけなら不要

#### ブラウザのメモリだけ？

**結論** — 共有・別端末には不向き

#### サーバーメモリ + API

**結論** — DB なしでもデモ〜小規模は可。本番長期は DB 検討

#### FileZilla で静的配信

**結論** — 可。データは **GAS 等の API** 経由。FileZilla でメモリ設定は不要

#### 実装は完了？

**結論** — **フロント MVP は進行中**。本番研修運用としては **Sheet API 未実装のため未完了**

## 4. スプレッドシート構成（確定版）

### 4.1 ブック構成

```
マスターブック
└── clients シート
    ├── clientId
    ├── spreadsheetId
    ├── displayName
    ├── enabled
    └── adminTokenHash

クライアント A / B 用スプレッドシート（各冊同型）
├── settings
├── rooms
├── responses
└── audit_logs
```

- 旧案の `meta` シートは廃止
- `apiToken` → **`adminTokenHash`**（マスター）
- 研修入室は **`rooms.accessCodeHash`**（平文コードはシートに保存しない）

### 4.2 クライアント追加 — 手作り必須か

#### A. 手動

**内容** — スプレッドシートをコピーしマスター `clients` に 1 行追加（検証用）

### **B. 自動（推奨）**

**内容** — **テンプレート 1 冊**を GAS がコピー → **`displayName` でリネーム** → settings 初期化 → `adminToken` 発行 → マスター登録

- API 案: `POST clients/provision`
- 運用者が 1 回だけ用意するのは **テンプレート用ブック** が中心

### 4.3 Postgres 移行

- フロントは `storage.ts` 窓口のみ
- API の JSON 形（`AppSettings` / `ParticipantSubmission`）を固定すれば、裏を Sheet → Postgres に差し替え可能（[SPREADSHEET-DATA.md §7](../docs/SPREADSHEET-DATA.md)）
