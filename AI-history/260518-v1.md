## 1. プロダクト前提（変わらない要件）

- **3DVista** が 360° パノラマ（画面の約 75%）を表示する。
- **ExpertEye360 受講者 Web** は **別 iframe** で **幅 100% × 高さ 25%** に埋め込む。
- iframe **内側だけ** が研修 UI。パノラマのモックや 75% 領域を **アプリ内に再現しない**（本番と同じ）。
- **管理者 Web** も別アプリ・別 URL・別 iframe。受講者ツアーの 25% 帯に載せない。
- 受講者・管理者は **別ポート開発時は別オリジン** → `localStorage` は共有されない（本番は同一ドメイン想定）。

### 3.6 受講者 UI のサイズ・レイアウト（試行と差し戻し）

**ユーザー指摘**: PC 埋め込み時、横幅が広いと文字・コンテンツが小さい。

**原因の整理（CSS）**:

- `participant-app.css` は `container-type: size` + `cqh` / `cqw` で 25% 帯に収める設計。
- カード高さ `clamp(..., 38cqh, 3.1rem)` の **上限 3.1rem** が `cqh` より小さく、カードが伸びない。
- カード文言 `clamp(..., 2.4cqw, 0.72rem)` は横長 PC で **上限 0.72rem に張り付く**。

**試行 1**: フォント・カードを `cqh` 中心に拡大、上限を緩和。

**試行 2**: ユーザー提案「中身は横幅 100% までなくてもいい」→ `--p-content-max` で中央・最大 44rem。

**結果**: ユーザー「もどして　バカすぎてあきれた」→ **試行 1・2 とも差し戻し**。`participant-app.css` は変更前の clamp 値に復帰。

**未解決**: 横長 PC での可読性は **未対応のまま**。今後の調整はユーザーと方針合意後に行うこと。

## 4. 技術メモ

### 4.1 サイズ単位

- iframe 内では `vh` / `vw` は **親ページのビューポート** を参照しやすく、25% 帯想定とずれる。
- 帯内レイアウトは `.p-shell` の **container query（`cqh` / `cqw`）** を使用。

### 4.2 開発時の注意

- PowerShell で `&&` が使えない環境あり → `cmd /c` や `;` を使用。
- 過去に `motion` タグが HTML/TSX に誤混入する事故あり（正しくは `div`）。
- `ParticipantPage.tsx` で JSX の `motion` 閉じタグ不整合で Vite エラーが出たログあり → 修正必要時は `motion` をすべて `div` に統一。
